# FarmOS Mobile — agent notes

React Native (Expo) client for the FarmOS ASP.NET Core API. Offline-first field
app for low-end Android; one-handed outdoor data entry.

## Expo HAS CHANGED

Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before
writing any native/config code. This project is on **SDK 57 / RN 0.86 / React 19**
with the **New Architecture** enabled.

## Non-negotiable rules

- **Decimal precision.** Money and quantities are branded `Money` / `Quantity`
  types (decimal.js-light under the hood). JavaScript `number` math corrupts
  them. The ESLint rule `local/no-money-arithmetic` bans `+ - * / % **` (and
  compound/`unary`/`++`) on those types — it is type-aware and will fail CI.
  Decimals travel as **strings** end to end and are stored as SQLite `TEXT`.
- **Package manager is pnpm.** `node-linker=hoisted` (see `.npmrc`) keeps Metro
  and native autolinking happy. Native build-script approvals live in
  `pnpm-workspace.yaml` (`allowBuilds`), not `package.json`.
- **TypeScript is `strict` + `noUncheckedIndexedAccess`.** No `any`.
- **Native folders are not committed** (CNG). `android/` and `ios/` are
  regenerated by `expo prebuild` / EAS Build. Edit config via `app.config.ts`
  and config plugins, never the generated native projects.
- **Config comes from `expo.extra`**, read through `src/lib/config/env.ts` —
  never `process.env` at runtime. Values are injected per profile from
  `.env.<APP_ENV>` by `app.config.ts`.

## Commands

- `pnpm typecheck` — `tsc --noEmit`
- `pnpm lint` / `pnpm lint:fix`
- `pnpm format` / `pnpm format:check`
- `pnpm start` — Expo dev server (Dev Client)
- `pnpm android` / `pnpm ios` — `expo run:*` (needs native toolchain)

Pre-commit runs `lint-staged` (eslint --fix + prettier) via Husky.

## Layout (`src/`)

- `app/` — Expo Router routes (file-based, typed routes on)
- `components/`, `hooks/`, `constants/` — UI + shared React
- `lib/` — cross-cutting utilities (`config/`, `decimal/`, `http/`)
- `db/` — SQLite (op-sqlite) + Drizzle schema/migrations _(Phase 2)_
- `sync/` — outbox + `/sync/batch` engine _(Phase 2)_
- `api/` — generated OpenAPI types + client _(Phase 3)_
- `features/` — vertical feature slices _(Phase 5)_
- `i18n/`, `theme/` — localization (en/ur, RTL) + design tokens _(Phase 4)_

Directories marked _(Phase N)_ are skeletons (`.gitkeep`) until that phase.
